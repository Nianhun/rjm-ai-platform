# 瑞吉明配方 AI 系统 10 期初版实现计划

> 目标：把当前 Python 原型 + Java 管理系统推进到“可演示、可试运行、可继续迭代”的初版。后续 agent 先读本文件，再进入 `docs/implementation_10_phase/phase_XX_*.md` 按期开发。

## 总体判断

当前项目已经完成了初版闭环骨架：Yuxi 知识导入、Python 推荐服务、Java 管理 API、工程师筛选、实验反馈、采购推荐、公式归档、DB 模式、反馈驱动推荐加权、学习权重审计表。

接下来不再发散做“大而全平台”，而是按 10 期把初版做实。每一期必须能独立验收，每一期结束都更新 `docs/agent_handoff.md`。

## 10 期路线

| 期数 | 名称 | 核心结果 | 状态 |
| --- | --- | --- | --- |
| 01 | 闭环基线冻结 | 明确当前可运行链路、修复文档与测试护栏 | 已基本完成，需最终整理 |
| 02 | DB 生产化最小配置 | Java `db` 模式可本地用 H2/SQLite 启动 | 完成 |
| 03 | 学习权重 API 与解释 | 前端/API 能看到为什么推荐变强 | 完成 |
| 04 | 工程师工作台增强 | 推荐、筛选、反馈、证据解释在一个页面顺畅操作 | 完成 |
| 05 | 供应商与采购闭环 | 根据配方原料生成供应商候选与采购状态 | 完成 |
| 06 | 知识库治理 | Yuxi 导入、证据、原料别名、关系可信度可管理 | 完成 |
| 07 | 实验批次管理 | 小试/中试批次、指标、问题、结论结构化 | 完成 |
| 08 | AI 推荐策略升级 | Python 推荐从规则加权升级为可插拔策略层 | 完成 |
| 09 | 部署与安全 | 本地/内网部署脚本、环境变量、基础权限 | 完成 |
| 10 | 初版验收演示 | 一键演示“保湿配方 -> 筛选 -> 实验反馈 -> 学习进化 -> 采购” | 完成 |

## 每期固定交付

- 代码：小步提交式变更，虽然当前目录不是 git repo，也要按可提交单元组织文件。
- 测试：Java 用 Maven，Python 用当前 bundled Python 直接执行测试文件。
- 文档：每期结束更新对应 phase 文档和 `docs/agent_handoff.md`。
- 验收：必须留下可复制命令和实际结果。

## 推荐执行顺序

1. 先完成 01 期收口，把已有能力稳定下来。
2. 02-04 期让系统能被真实配方工程师试用。
3. 05-07 期把业务闭环补齐，尤其是采购与实验批次。
4. 08 期再升级 AI 策略，避免过早复杂化。
5. 09-10 期做部署、权限和演示验收。

## 时间预估

- 可演示初版：按当前进度和一人公司节奏，约 3-5 天。
- 内部试运行初版：约 2-4 周。
- 10 期全部完成到“可交付初版”：若每天持续推进，约 10-15 个高强度工作日；若穿插业务确认，约 3-4 周。

## 后续 agent 启动提示

后续 agent 收到“继续”时：

1. 读 `docs/agent_handoff.md`。
2. 读本文件。
3. 找到第一个状态不是“完成”的 phase 文档。
4. 先跑该文档的“开始前验证”。
5. 按任务顺序开发。
6. 每完成一个任务就跑对应验收命令。
